# Learning Cards

Each card has four layers: **L0** a twelve-year-old can follow → **L1** the mechanism → **L2** how to use it → **limit** when it fails. Plus the gap evidence.

---

## 迭代安全

> 它开始改自己了。改到哪一步必须有人拦住？

### L37 · 自改绊线

`self-modification-tripwire` · `components/L37-self-modification-tripwire/`

- **L0（人话）** 有些东西不能自己改：记忆、规则、密钥。哪怕改的是「优化」，也得先问一声。
- **L1（本质）** 四红区：记忆层 / 发布门 / 规则 / 凭据。命中即 STOP-need-authorization。它防的是最隐蔽的一类事故：以「改进」为名的越权。
- **L2（怎么用）** 每次批量改文件前先跑一次路径清单；STOP 就停下来要授权，不自行判断「这次没关系」。
- **边界** 靠路径关键词匹配；改名或迁移目录会漏。
- **空白证据** 文件权限管读写，缺「按语义红区判定是否越权」的绊线（抽样未单列）。

### L38 · 不变量快照

`invariant-snapshotter` · `components/L38-invariant-snapshotter/`

- **L0（人话）** 改东西的时候，有些「必须永远成立」的事容易被碰坏：比如「零依赖」「自检必须全过」。这工具帮你盯着。
- **L1（本质）** 迭代前后各拍一张不变量快照，比对三类：消失（broken，最严重）、变形（changed）、新增。判据：消失比变形更严重，因为消失通常意味着被静默删掉。
- **L2（怎么用）** 大改前后各拍一次；出现 broken 就回滚，别先解释。
- **边界** 只比对「你列出来的」不变量；没列的它不管。
- **空白证据** 属性测试管代码不变量，缺「跨迭代快照比对并要求解释」的原语（抽样未单列）。

### L39 · 回滚就绪检查

`rollback-readiness-check` · `components/L39-rollback-readiness-check/`

- **L0（人话）** 「有备份」和「能回滚」不是一回事。备份没试过，真出事时才发现坏了，那就晚了。
- **L1（本质）** 四要素（备份存在 / 备份已验证 / 步骤有文档 / 责任人明确），三档 R0-blind / R1-unverified / R3-ready。核心：只有全齐才叫可回滚，只备份过叫「以为可回滚」。
- **L2（怎么用）** 任何不可逆操作前跑一次；不到 R3 就先等，或者改成可逆的两步做。
- **边界** 「已验证」需人确认；工具无法自己演练回滚。
- **空白证据** 备份工具很多，缺「回滚就绪度分级」的体检原语（抽样未单列）。

### L40 · 爆炸半径估算

`blast-radius-estimator` · `components/L40-blast-radius-estimator/`

- **L0（人话）** 改一行代码和改十个文件、影响一万个用户，风险差得远。这工具先量一下「这一改会炸多大」。
- **L1（本质）** 半径 = 文件数 + 2×调用方 + 10×用户可见；回滚不就绪直接乘 2。这不是保守，是乘法：不可逆 × 大范围 = 灾难。四档给分批/灰度建议。
- **L2（怎么用）** 动手前估一次；R2 以上必须分批，别一次推完。
- **边界** 三轴权重是经验值；调用方数量难准确统计。
- **空白证据** 变更管理靠评审会，缺「改动前量化半径」的计算器（抽样 1 命中）。
